# v5.3 검증 표본 라벨 방법 (1쪽)

파일: `outputs/validation/holdout_v53.blind.csv` (30행). 자동 판정 결과는 이 파일에 없다. 라벨을 마칠 때까지 `holdout_v53.key.csv`를 열지 않는다.

## 각 행에서 볼 것
- `product_code`, `ref_month`(기준월), `look_at`(무엇을 볼지)
- `benefit_window` / `substitute_window`: 기준월 전후 3개월의 급여목록 / 대체조제 목록 원문(업체 / 제품명 / 규격 / 금액 / 비고). `(없음)`은 그 달 목록에 이 제품이 없다는 뜻
- `same_item_codes`: 같은 허가(품목기준코드)를 쓰는 다른 제품코드(기간 제한 없음)
- `same_ingredient_candidates`: 같은 주성분의 다른 제품코드 중 기준월 전후 3개월 안에 처음 또는 마지막으로 실린 것
- 원본이 더 필요하면 `data/raw/`의 해당 달 파일을 직접 본다. 외부 자료를 썼으면 `truth_note`에 출처를 적는다

## 정답 칸
| 칸 | 쓰는 법 |
|---|---|
| `truth_event` | 아래 11개 중 하나 (글자 그대로) |
| `truth_date` | 그 변화가 효력을 가진 날 `YYYY-MM-DD`. 목록에 날짜가 없으면 그 변화가 처음 보인 목록의 1일. 알 수 없으면 비운다 |
| `truth_note` | 근거(어느 달·어느 목록·어느 비고를 봤는지), 망설인 점 |

## `truth_event` 범주
| 범주 | 뜻 |
|---|---|
| 예고대로 시행 | 비고에 적힌 예고가 적힌 날짜·금액 그대로 목록에 반영됐다 |
| 다른 금액·늦게 시행 | 예고가 반영됐지만 금액이 다르거나 적힌 날짜보다 늦게 반영됐다 |
| 시행 안 됨 | 예고한 날이 지나고 결과를 볼 수 있는데도 반영되지 않았다 |
| 아직 모름 | 분석 기간(2025-12) 안에서는 반영 여부를 알 수 없다(법원 집행정지가 계속되는 경우 포함) |
| 이어받기(다른 회사) | 같은 약이 다른 회사 이름으로 새 코드에 실리고 옛 코드는 사라졌다 |
| 이어받기(같은 회사) | 같은 회사가 같은 약을 새 코드로 다시 실었다(코드만 바뀌었거나 이름·허가를 바꿔 다시 실음) |
| 삭제 | 제품이 목록에서 빠졌다(급여중지 예고 뒤 삭제된 경우 포함) |
| 해제 | 멈춰 있던 보험 적용이 다시 시작됐다 |
| 예고 없는 변화 | 비고에 미리 적힌 것 없이 금액이 바뀌었다 |
| 신규 등재 | 목록에 처음 실렸다(같은 약의 이어받기가 아님) |
| 기타 | 위 어디에도 맞지 않는다. `truth_note`에 무엇인지 적는다 |

- 한 행에 변화가 여럿이면 `look_at`이 가리키는 것 하나만 고른다.
- 판단이 어려우면 가장 가까운 범주를 고르고 `truth_note`에 이유를 적는다. 라벨을 마친 뒤 정답을 고치지 않는다(고친다면 처음 값과 고친 값을 둘 다 남긴다).
