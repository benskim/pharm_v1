# PLAN_P2 — 성분×시도 원외처방 수요 예측과 발주 시뮬레이션 (2026-11-14)

## 1. 목표와 주장

**질문** (2026-11-16 재정의): **사용통계 공백 5개월을 목록 신호로 얼마나 메울 수 있나.** 발간월 M의 1일에는 사용통계가 M−5까지만 공개되어 있다 (`usage_lag_months = 5`, P1 S6과 같은 값). 공개 사용통계만으로 공백 달(M−4 ~ M)과 다음 달(M+1)의 성분별 원외처방 수요를 얼마나 맞출 수 있는가. P1의 선행 신호(목록 ≤ M)를 넣으면 나아지는가 (M3 대 M2). 발주 시뮬레이션은 선택이다.

**주장의 형태**: "신호를 넣으면 개선된다"를 미리 정하지 않는다. 개선이 없으면 그대로 보고한다. 신호는 예측값에 직접 반영하지 않고 **특징으로만** 넣는다 (CLAUDE.md 핵심 원칙).

| 항목 | 값 |
|---|---|
| 목표 변수 | 원외 청구수량 (보조: 청구건수) |
| 단위 | 성분 4자리 × 시도 × 월. 전국 = 시도 합 |
| 기간 | 2018-01 ~ 2025-12 (96개월) |
| 예측 시점 (origin) | 발간월 M의 1일. 쓸 수 있는 자료: 사용통계 ≤ M−5, 목록 ≤ M. M의 범위는 2023-01 ~ (T2에서 정한다, 예측 대상 M+1 ≤ 2025-12) |
| 예측 대상 | M−4, M−3, M−2, M−1, M (공개 공백 5개월) + M+1. 마지막 관측월 M−5에서 1~6개월 앞, **예측 기간 6개를 따로 보고** |
| 데이터에 없는 것 | 약국 단위 구매·재고·판매. 일반의약품(비급여). 업체 2곳 이하 성분 |

## 2. 대상 성분

1. **관측 조건**: 2018-01~2025-12 전국 기준 96개월 내내 관측된 성분 (비공개로 빠진 달이 없음). 중간에 나타난 성분은 별도 표로만 보고한다.
2. **규모 조건**: 2022년 원외 청구수량 상위 성분. 개수는 `config/params.yaml`의 `p2_top_n` (기본 200).
3. **주력 묶음** (2026-11-14 확정): 급여목록 `분류` **141, 222, 229, 618**. 114는 겨울/여름 비율 1.05로 계절성이 없어 "나머지"에 두고, 계절 묶음과 비계절 묶음의 대조군으로 쓴다. 614(2022 원외 수량 0.74억, 1.182)와 619(96개월 관측 성분 1~2개)는 넣지 않는다. 겨울/여름 비율 = 2022~2025 원외 청구수량의 겨울(11~3월) 월평균 ÷ 여름(6~8월) 월평균 (`DECISIONS.md`).
4. **기관 범위**: 기본은 전체 요양기관의 원외. 보조 분석으로 의원급 원외만 따로 (약국 수요에 가장 가까운 대리변수). 요양기관종별 코드는 S0에서 확인한다.

커버리지 보고: 대상 성분 수, 전체 원외 청구금액 중 비중, 비공개로 빠진 성분의 목록 기준 비중.

## 3. 특징

| 묶음 | 특징 | 사용 가능 기간 | 누수 규칙 |
|---|---|---|---|
| 자기 시차 | 시차 h..h+11, 12개월 전, 이동평균 | 전체 | 예측 기간 h보다 가까운 시차 금지 |
| 달력 | 월, 영업일 수, 설·추석이 든 달 | 전체 | 달력은 미리 알 수 있음 |
| 구조 | 시도, 성분의 약효분류, 연령 구성비(직전 12개월) | 전체 | 직전 값만 |
| **선행 신호** (P1) | 예고 인하 폭 × 제품 비중 × 노출 일수, 등재 예정 업체 수, 급여정지 제품 수, 유효 업체 수 변화 | 2022-01 ~ | **M월 스냅샷에서 만든 신호 특징은 M+1월 이후의 origin에서만 쓴다** (사용자 결정 2026-11-14 9차). **주 모형은 그 달 파일의 토큰을 그 달 1일에 알 수 있었던 것으로 쓰고, `in_month_dated`(날짜가 그 달 2일~말일) 토큰·신호를 뺀 결과를 민감도로 함께 낸다** (사용자 결정 2026-11-15). 민감도에서는 등재 예정 신호 342개가 모두 빠져 등재 특징이 사라진다. **뒤 스냅샷이 와야 정해지는 칸(확인 달, `check_month_by_date`, 실현 달, 확인까지 일수, `last_seen_month` 등, 목록은 `src/pbd/ledger/posthoc.py`)은 특징으로 쓰지 않는다.** 신호 결과(outcome)는 origin보다 앞선 확인 달의 신호에서만 쓴다 (과거 실현율). 시험 `tests/test_p2_posthoc.py` (사용자 결정 2026-11-15) |
| 외부 (선택) | 독감 의사환자 분율 (주별 → 월) | 파일 확보 시 | origin 이전 주까지 |

**공개 시차** (2026-11-16 사용자 확인): 사용통계는 발생 후 5개월 뒤 초본이 공개되고 이후 매달 과거 자료 수정본과 새 초본이 함께 공개된다. `config/params.yaml`의 `usage_publication_lag_months = [5, 0]`: **5가 기본 평가**, 0은 참고(이상적). 자기 시차 특징은 M−5 이하 사용통계만 쓴다.

**목록 신호의 시점** (2026-11-16 사용자 결정): **주 정의는 "발간월 M의 1일에 M 스냅샷까지"**다. M월 목록은 전달 하순에 공개되므로 M 1일에는 이미 볼 수 있다 (P1 S6 리포트와 같은 시점). 위 표의 9차 규칙("M월 스냅샷에서 만든 신호 특징은 M+1월 이후의 origin에서만")은 **T3의 보수적 민감도**로 남긴다. `in_month_dated` 민감도도 그대로 낸다.

## 5. 평가

- 시간순 롤링 origin(발간월 M). 학습은 M−5 이하 사용통계와 M 이하 목록만.
- **예측 기간 6개(M−4 ~ M+1)를 따로 보고한다.** 공백 달에 효력이 생긴 이벤트(가격 변경·등재·삭제·정지의 유효일이 M−4 ~ M)가 있는 성분·월과 없는 성분·월을 따로 본다. M3 대 M2 비교는 그대로 둔다.
- 공개 시차 5개월이 기본 평가, 0개월은 참고.
- **한계**: 실제 발간 시점의 M−5 자료는 초본이지만 우리는 2026-11 수정본으로 학습·평가한다. 결과가 낙관적일 수 있다 (BACKLOG X11).
- 지표: MASE (계절 척도 12), WAPE, 분위 예측은 pinball loss와 P90 포함률.
- 나눠서 보고: 예측 기간별, 독감 유행기(11~3월)와 비유행기, 신호가 있던 성분·월과 없던 성분·월, 주력 묶음과 나머지.
- 코로나 시기 (2020~2021): 학습에는 포함하되 플래그 특징을 둔다. 이 시기를 origin으로 한 평가는 따로 보고한다 (본 비교에는 넣지 않음).
- M3 대 M2의 차이는 성분별 오차 차이에 대한 부호 검정 또는 Diebold-Mariano 검정으로 본다. 유의하지 않으면 "차이 없음"으로 쓴다.

## 6. 발주 시뮬레이션

**설정**: 시도 × 성분마다 가상의 창고 하나. 월 1회 검토, 리드타임 1개월. 발주 목표 = 다음 달 예측 분위수 − 현재 재고.

| 정책 | 발주 기준 |
|---|---|
| 기준 | M0 예측 × (1 + 고정 안전계수) |
| 예측 기반 | M2 또는 M3의 분위수 (분위 수준은 결품·재고 비용 비율에서 정함) |

- 결과: 결품률(수요 대비 부족분 비율), 평균 재고일수, 둘의 교환 곡선. 비용 비율 여러 값에 대해.
- 실제 수요는 사용통계 실측값으로 둔다.
- **한계를 결과보다 먼저 쓴다**: 약국 단위가 아니다. 리드타임·비용 비율은 가정이다. 시도 합계의 변동은 개별 약국보다 훨씬 작다.

## 7. 단계와 완료 기준

S0은 P1과 공통이다 (`PLAN_P1.md` §6).

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **T1** 예측 마트 | `fc_panel` (성분×시도×월), 대상 성분 선정, 커버리지 표 | 원본 재집계 합 = 마트 합. 첫 관측월 제외 규칙 테스트. 대상 선정 기준과 탈락 단계표 |
| **T2** 기준선 | M0, M1, 롤링 평가 틀 | 누수 테스트 통과 (미래 행을 바꿔도 과거 origin 예측이 안 바뀜). 오차표 |
| **T3** 전역 모델·신호 | M2, M3, 신호 특징 (P1 S3 이후) | **T3 두 기준** (2026-11-16 사용자 결정, 10차를 대체): M3를 "M월 파일을 M월 origin부터 사용"(**주 결과**, M월 목록은 전달 하순 공개)과 "M+1월 origin부터 사용"(9차 규칙, **보수적 민감도**) 두 기준으로 돌려 차이를 보고한다. 신호 특징 누수 테스트 (origin M의 특징은 M월까지의 스냅샷만으로 만든다: M+1월 이후 스냅샷을 지워도 특징 동일. 민감도는 M−1월까지. 나중에 고쳐 쓴 `exposure_frac`을 쓰지 않고 origin 시점의 `signal_ledger` 행만 쓰는 경우 포함). M3 대 M2 비교표와 검정 |
| **T4** 분위·발주 | 분위 예측, 정합(선택), 발주 시뮬레이션 | P90 포함률 보고. 정책별 교환 곡선. 한계 절 먼저 |
| **T5** 문서 | README 절, 2쪽 요약 | 개선이 없던 결과도 요약에 포함 |

**최소판** (2026-11-16 재정의): 주력 묶음 성분 × 전국, M0·M2·M3, 예측 기간 6개(M−4 ~ M+1). 발주 시뮬레이션은 선택.

T2·T3의 누수 시험은 위 시점 정의를 따른다: 발간월 M의 예측은 M−4 이후 사용통계와 M+1 이후 스냅샷을 바꿔도 같아야 한다. T3의 두 기준은 **"M월 파일을 M월 origin부터"가 주 결과**, **"M+1월 origin부터"(9차 규칙)가 보수적 민감도**다 (2026-11-16 사용자 결정, 위 T3 행의 "비교용 상한·결과로는 뒤의 것만"을 대체).
