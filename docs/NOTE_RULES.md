# NOTE_RULES — 비고 유형별 규칙

원본: 2026-11-13 점검 (`NOTE_RULES_v3`). 점검 범위는 2024-01~2025-12 스냅샷 24개(비고 있는 행 11,876개)와 2026-11-01 원본. 재현은 `reference/precheck_v3.py`, `reference/secondary/precheck_v3_note_rules.py`.

**2026-11-14 변경**: 미래 날짜 비고는 선행 신호로 다룬다 (§2). 분석 기간은 2022-01~2025-12. 2022~2023에서 새 문형이 나오면 S0에서 보고하고 사용자가 규칙을 정한다.

## 1. 비고 유형과 규칙

1차 구현 대상: R1~R7, P1~P3. R8은 2차 (`BACKLOG.md`).

## 2. 신호 판정

`note_token.is_future = (date > 스냅샷 기준일)`. 기준일은 스냅샷의 실제 기준일(예: 2025-03-04)이지 월 1일이 아니다.

| 토큰 type | is_future = true | is_future = false |
|---|---|---|
| R1 등재 | 신호 (`LISTING_SCHEDULED` 또는 `LISTING_NOTE_EXISTING`) | 등재일 근거 (진입 이벤트의 날짜) |
| R2 가격 예고 | 신호 (`PRICE_PENDING`) | 이미 적용된 가격의 날짜 근거 |
| R3 급여정지 | 미래 정지 신호. 표본에 없음. 나오면 S0 보고 | 상태 근거 |
| R4 집행정지 | 신호로 쓰지 않음 (법원 결정일) | 상태 근거 (`stay_flag`) |
| R5 집행정지 해제·인하 | 신호 (`STAY_RELEASE_PRICE`) | 이벤트 날짜 근거 |
| R6 급여정지 해제 | 미래 해제 신호. 표본 1건, 판정은 S0에서 확인 | 이벤트 날짜 근거 |
| R7 산정불가 | 해당 없음 | 상태 근거 |

## 3. 표본에서 확인한 사실 (참고)
- 집행정지 중에도 가격은 바뀐다. 집행정지는 특정 처분 하나의 효력만 멈추므로 다른 사유의 인하는 적용된다. "집행정지 = 가격 고정" 규칙은 두지 않는다.
- 한 칸에 집행정지와 다른 유형이 같이 적힌 경우는 P1(건별 분리)로 처리하므로 별도 규칙이 필요 없다.

2. 2022~2023 스냅샷의 새 문형 (S0).
