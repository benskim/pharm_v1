# 공개 의약품 데이터로 본 급여목록 처분 예고와 처방 수요

건강보험심사평가원 급여목록의 비고에 미리 적힌 처분 예고(약가 인하·신규 등재·급여중지)를 날짜별 변화 기록표로 정리하고, 예고대로 실행된 비율과 영향 규모를 매달 1일 리포트로 낸다(P1). 같은 정보를 더하면 성분별 전국 처방량(원외 처방, 약국 단위 아님) 예측(마지막 자료에서 6개월 앞, 공개 시차 5개월 가정)이 나아지는지도 시험했다(P2). 아래 결론과 숫자는 스크립트가 결과 파일에서 생성한다.



## 빠른 확인 (표본 데이터, 약 3분)
원본 전체 없이 저장소의 코드와 표본만으로 돌려 본다. 표본 parquet 8개는 [docs/DATA.md](docs/DATA.md) "원본 파일 목록"의 `data/sample/` 줄과 같은 파일을 `data/sample/`에 둔다.
```
make venv            # 새 가상환경, requirements.txt 설치          (실측 54초)
make check-sample    # 표본 회귀: reference/precheck_v3_output.md와 같아야 한다  (실측 3초)
make test            # 자동 시험. 원본 DB가 필요한 시험은 건너뛴다   (실측 2분 12초: 239개 통과, 125개 건너뜀)
```
실측: 2026-11-19, v1.0을 새 폴더에 내려받아 `data/sample/`만 둔 상태 (Apple 노트북 1대).

## 전체 재현 (약 2~3.5시간)
원본 127개 파일을 [docs/DATA.md](docs/DATA.md)의 출처에서 받아 `data/raw/`에 두고 크기·SHA-256을 대조한 뒤(`python -I scripts/data_manifest.py --check`) `make all`을 돌린다. 적재 → 변화 기록표 → 분석 → 리포트 → 처방 수요 예측과 진단 → 문서 → 전체 시험까지 한 번에 돈다(시험 수는 v1.0 364개, v1.1 369개). 기록과 숫자 대조 방법은 [reports/REPRODUCTION.md](reports/REPRODUCTION.md).

## 핵심 결론

**한 줄 요약**: 급여목록에 미리 적힌 약값 인하와 급여중지 처분은 대부분 실현됐고, 법원 집행정지로 막힌 것은 처분 기준으로 소수(급여중지 91건 중 3건, 약값 인하 509건 중 2건)였다. 공개 사용통계로 성분 처방량을 예측할 때 기계학습 모델은 작년 같은 달 값과 대체로 비슷했고, 급여목록의 예고 정보는 예측을 개선하지 못했다.

1. **급여목록에 미리 적힌 처분은 대부분 실현됐고, 법원 집행정지로 막힌 것은 처분 기준으로 소수였다.**
   - 약값 인하: 결과가 난 약값 인하 예고(제품 4,669개) 중 99.7%가 실현됐다(다른 금액·늦은 시점 포함). 예정일에 예고대로 실현된 것은 98.3%다. 대체조제 목록에만 남은 막힌 처분까지 넣으면 현재까지 실행된 비율은 98.4%, 법원 집행정지가 걸린 비율은 3.2%(151/4,746개 제품, 그중 77개는 집행정지가 끝난 뒤 실행)다.
   - 급여중지: 급여중지 예고는 처분 91건(65개 회사, 제품 203개)이었고, 그중 3건(동아에스티 72개 제품, 경보제약 23개, 삼성제약 1개)이 법원 집행정지로 막혔다. 제품 수로 세면 47.3%지만, 큰 처분 몇 건이 제품 수를 부풀린 값이다. 급여목록 표시만으로 세면 제품 기준 36.0%이며, 경보제약은 외부 보도로만 확인했다. 결과가 난 급여중지 예고 중 예정일에 그대로 시행된 비율은 32.0%이고, 나머지 실현은 늦은 시행과 삭제다.
   - 예고 없는 변화: 가격이 바뀐 제품의 66.7%(9,370/14,041)는 급여목록 비고에 미리 적히지 않았다. 이 가운데 81.7%는 일괄 인하가 있었던 3개 달이고, 2023-09 제네릭 재평가 한 번이 7,371건이다. 이 재평가는 목록 밖에서 미리 보도됐다. 일괄 인하 3개 달을 빼면 26.8%다.
2. **기계학습 모델은 작년 같은 달 값과 대체로 비슷했고, 이례적인 기간에 덜 빗나갔다.**
   - 미리 정한 주 대상(호흡기 계열 32개)에서는, 사용통계가 5개월 늦게 공개된다고 두고 마지막 자료에서 6개월 앞을 예측하면 모델이 작년 같은 달 값보다 나빴다(WAPE 29.1% 대 23.9%).
   - 결과를 본 뒤 원래 계획 범위로 넓힌 상위 200개에서는 모델이 조금 나았다(11.0% 대 12.0%, 청구금액 가중 6.7% 대 8.5%). 그 차이는 거의 모두 2023년 상반기에서 나왔다(달별 오차 평균: 작년 값 18.0% 대 모델 11.7%). 이때 처방량이 전년 같은 달보다 크게 늘어(중앙값 +14.5%, 2024·2025년 상반기는 약 -1%) 작년 값(2022년)이 크게 빗나갔다. 코로나 뒤 회복기와 겹친다(호흡기 32개는 2022년 상반기가 2019년의 85% 수준). 나머지 달에는 둘이 거의 같았다(11.0% 대 10.9%). 달별 총오차 검정으로는 유의하지 않았다(청구금액 가중으로는 유의).
   - 덜 집계됐을 수 있는 최근 12개월을 빼도 같은 모양이었다(상위 200개 11.0% 대 12.3%, 32개는 작년 값이 더 나음).
   - 수정이 끝난 자료로 지난달까지 볼 수 있다고 가정하면 상위 200개의 1개월 앞 오차는 7.2%였다(32개는 13.6%). 이는 실제로 얻을 수 없는 상한이며, 예측 거리가 짧아진 효과와 자료 신선도의 효과가 섞여 있다. 1개월 앞에서 멀어질수록 오차가 커졌다(2023-01 ~ 2024-12에 시작한 예측으로 잰 곡선에서 2개월 앞이 1개월 앞 대비 약 25%(상위 200개)·33%(32개)).
   - 2023년 상반기 분석은 시기별 비교와 관련성만 보였고 원인을 증명하지 않는다.
3. **성분 합계 처방량 예측은 급여목록 예고 정보를 넣어도 나아지지 않았다(세 대상, 시차 0·5).** 실제로 일어난 변화를 미리 넣은 시험은 성분 32개에서만 했고, 거기서도 나아지지 않았다. 일부러 넣은 20% 효과도 일부만 찾을 만큼 검출력이 낮아 '효과가 없다'고는 말하지 않는다. 처방량이 상한금액에 둔감해서인지, 성분 안에서 제품이 바뀌어서인지는 성분 단위 자료로 구분할 수 없다. 가격을 미리 알 때 줄일 수 있는 오차의 상한은 금액 변화 분해로 근사하면 약 2%(성분 32개 기준)다. 대상은 업체가 3곳 이상인 성분(공개 기준)이다.

**의미**:
- 급여목록의 처분 예고는 처분 기준으로 대부분 실현됐다. 약국 알림에 쓸 수 있고, 급여중지는 법원에서 막힐 수 있다는 표시를 함께 두는 것이 맞다(시험하지 않은 제안).
- 공개 통계 기반 예측은 평상시에는 작년 같은 달 값과 비슷했고, 코로나 회복기처럼 이례적인 기간에 덜 빗나갔다. 바로 쌓이는 약국 주문·판매 자료가 예측을 더 낫게 할지는 검증하지 않은 가정이다.
- 급여목록 예고 정보는 성분 전체 수요 예측보다 가격·재고 위험 알림에 맞는 정보다(시험하지 않은 제안).

**판정 정밀도**: 규칙을 고치기 전 판정 엔진(v5.2)을 사람 정답 30건(판정 유형별 3건씩, 작성자 1인)과 맞춰 보면 유형 일치는 83.3%였다. 불일치 건만 다시 보고 2건을 고치면 90.0%다(고친 2건은 같은 허가를 이은 경우로, 급여 사건으로는 신규 등재로 볼 여지도 있다). 이 불일치를 보고 규칙을 고친 v5.3의 정밀도는 별도 검증 표본으로 잰다. 유형별 같은 수로 뽑아 모집단 정밀도가 아니며 놓친 사건(재현율)은 재지 않았다. 날짜 일치는 대부분 '그 달 1일' 관례가 양쪽에 같이 적용된 결과라 날짜 판정의 검증으로 보지 않는다.

**용어** — **급여목록**: 건강보험이 적용되는 약과 상한가격의 공식 목록(매달 새 파일). **비고**: 목록의 메모 칸. 앞으로의 처분(예: "'25.7.1. 인하")이 미리 적힌다. **변화 기록표**: 월별 목록 파일을 비교해 언제 무엇이 바뀌었는지 날짜별로 정리한 표. **WAPE**: 예측이 빗나간 양의 합 ÷ 실제 처방량의 합(작을수록 좋다). **원외 처방**: 병원 밖 약국에서 조제되는 처방. **급여중지**: 건강보험 적용을 일정 기간 멈추는 처분. **집행정지**: 처분에 소송이 걸렸을 때 법원이 판결 전까지 처분의 효력을 멈추는 결정. **양도양수**: 제품의 허가를 다른 회사가 넘겨받아 같은 약이 새 코드로 다시 실리는 것.


## 필요한 데이터
원본은 저장소에 없다. [docs/DATA.md](docs/DATA.md) §1의 표대로 다음을 배치한다.
- `data/raw/`: `benefit/`, `substitute/`, `usage/`(사용통계 원본 96개 CSV), `master/`, `orangebook/`
- `data/sample/`: 표본 parquet 8개 ([data/sample/README.md](data/sample/README.md))

## 설치와 실행
Python 3.11, 디스크 약 5GB (원본 2.3GB, DB 약 1.7GB).
```
make venv                      # .venv 생성, requirements.txt 설치 (약 1~2분)
make check-sample              # 표본 회귀: reference/precheck_v3_output.md와 같아야 한다
make all                       # 적재 → 표본 회귀 → 변화 기록표 → 분석 → 리포트 → P2 → 문서 → 전체 시험
make p2-min                    # P2: 예측용 자료 → 기준 예측 → 모델·진단 → 문서
make report MONTH=2024-09      # 한 달 리포트 → outputs/reports/P1_report_2024-09.md, outputs/dashboard/2024-09/
make test                      # 전체 자동 시험
```
깨끗한 클론 재현(2026-11-19, v1.0 = 6bb4d23): 1차(e933957)는 v4 보관 스크립트 버그로 시험 8개가 실패해 고쳤고, 2차(v1.0)는 새 가상환경에서 처음부터 전체 통과했다(`make all` 1시간 47분, 시험 364개, 결과 CSV 31개·문서 6개가 커밋된 결과와 같음. [reports/REPRODUCTION.md](reports/REPRODUCTION.md)). 이전 판정 규칙 시점의 기록은 [docs/REPRODUCE_LOG.md](docs/REPRODUCE_LOG.md), 그 결과는 `outputs/v4_legacy/`에 읽기 전용으로 있다. `make all`은 P2(`make p2-min`)까지 돈다. 사용자가 정답을 단 검증 표본(`outputs/validation/`)은 저장소에 있고 실행이 덮어쓰지 않는다.

## 예시 리포트
- [2024-09](outputs/reports/P1_report_2024-09.md): 시타글립틴 인하 예고, 아픽사반 등재 예고
- [2025-11](outputs/reports/P1_report_2025-11.md): 토파시티닙 등재 예고, 11월 정기 정비 삭제 611건

리포트는 발간 달까지의 목록과 5개월 전까지의 사용통계만 쓴다. 같은 입력이면 같은 파일이 나오는지는 2026-11-19 깨끗한 재현에서 확인했다.
