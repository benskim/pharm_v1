# 공개 의약품 데이터로 본 급여목록 처분 예고와 처방 수요

건강보험심사평가원 급여목록의 비고에 미리 적힌 처분 예고(약가 인하·신규 등재·급여정지·중지 예정)를 날짜별 변화 기록표로 정리하고, 예고대로 실행된 비율과 영향 규모를 매달 1일 리포트로 낸다(P1). 같은 정보를 더하면 성분별 전국 처방량(원외 처방, 약국 단위 아님) 예측(마지막 자료에서 6개월 앞, 공개 시차 5개월 가정)이 나아지는지도 시험했다(P2). 아래 결론과 숫자는 스크립트가 결과 파일에서 생성한다.



## 빠른 확인 (표본 데이터, 약 3분)
원본 전체 없이 저장소의 코드와 표본만으로 돌려 본다. 표본 parquet 8개는 [docs/DATA.md](docs/DATA.md) "원본 파일 목록"의 `data/sample/` 줄과 같은 파일을 `data/sample/`에 둔다.
```
make venv            # 새 가상환경, requirements.txt 설치          (실측 54초)
make check-sample    # 표본 회귀: reference/precheck_v3_output.md와 같아야 한다  (실측 3초)
make test            # 자동 시험. 원본 DB가 필요한 시험은 건너뛴다   (실측 2분 12초: 239개 통과, 125개 건너뜀)
```
실측: 2026-11-19, v1.0을 새 폴더에 내려받아 `data/sample/`만 둔 상태 (Apple 노트북 1대).

## 전체 재현 (약 2~3.5시간)
원본 127개 파일을 [docs/DATA.md](docs/DATA.md)의 출처에서 받아 `data/raw/`에 두고 크기·SHA-256을 대조한 뒤(`python -I scripts/data_manifest.py --check`) `make all`을 돌린다. 적재 → 변화 기록표 → 분석 → 리포트 → 처방 수요 예측과 진단 → 문서 → 전체 시험까지 한 번에 돈다(시험 수는 v1.0 364개, v1.1 369개). 기록과 숫자 대조 방법은 [reports/REPRODUCTION.md](reports/REPRODUCTION.md).

## 핵심 결론

**한 줄 요약**: 급여목록에 미리 적힌 약값 인하 예고는 대부분 실현됐고, 급여정지·중지 예정이 법원 집행정지로 막힌 경우는 처분 기준으로 소수(급여정지·중지 91건 중 3건, 약값 인하 509건 중 2건)였다. 공개 사용통계로 성분 처방량을 6개월 앞 예측할 때 기계학습 모델은 작년 같은 달 값보다 나았지만 통계 모형(ETS)과는 구분되지 않아, 기본 운영 모델로 ETS를 권고한다. 2026년 자료로 한 평가는 잠정이며 최종 평가가 남아 있다.

1. **약값 인하 예고는 대부분 실현됐고, 급여정지·중지 예정이 법원 집행정지로 막힌 경우는 처분 기준으로 소수였다.** 급여목록 비고의 예고는 이미 발표된 고시를 옮겨 적은 것이라 실현율이 높은 것이 자연스럽다.
   - 약값 인하 예고: 결과가 난 제품 4,669개 중 99.7%가 실현됐다(다른 금액·늦은 시점 포함, 처분 기준 509건 중 508건). 예정일에 예고대로 실현된 것은 98.3%다. 대체조제 목록에만 남은 막힌 처분까지 넣으면 현재까지 실행된 비율은 98.4%, 법원 집행정지가 걸린 비율은 3.2%(151/4,746개 제품, 그중 77개는 집행정지가 끝난 뒤 실행)다.
   - 급여정지·중지 예정: 처분 91건(65개 회사, 제품 203개) 가운데 결과가 난 제품 전부가 실현된 처분은 88건(96.7%)이다(실현에는 늦은 시행과 삭제 포함). 나머지 3건은 법원 집행정지로 막혔다(동아에스티 72개 제품, 경보제약 23개, 삼성제약 1개, 비고 표기는 셋 다 '급여정지'). 제품 기준으로는 현재 실현율 53.7%, 결과가 난 것 중 예정일에 그대로 시행된 비율 32.0%다. 막힌 제품 비율 47.3%는 큰 처분 몇 건의 제품 수가 좌우한 값이다(급여목록 표시만으로 세면 36.0%, 경보제약은 외부 보도로만 확인).
   - 비고 미기재 약가 변경: 가격이 바뀐 제품의 66.7%(제품 단위 약가 변경 9,370/14,041건)는 비고에 따로 적히지 않았고, 목록 고시로 시행됐다(시행일은 비고에 같은 금액과 함께 적힌 지난 날짜, 없으면 그 달 1일). 이 가운데 81.7%는 일괄 인하가 있었던 3개 달이고, 2023-09 제네릭 재평가 한 번이 7,371건이다. 일괄 인하 3개 달을 빼면 26.8%다.
2. **6개월 앞 성분 처방량 예측: 기계학습 모델은 작년 같은 달 값보다 나았지만, 통계 모형(ETS)과는 구분되지 않았다. 기본 운영 모델로 ETS를 권고한다.**
   - 방법: 2018-01 ~ 2022-07에 매달 공개된 성분 501개(2018-12 ~ 2019-11 공개 원외 청구금액의 93.8%)를 대상으로 했다. 사용통계가 5개월 늦게 공개된다고 두고, 마지막 자료에서 6개월 앞 처방량을 예측했다. 대상·가중치·비교 방법·판정 기준은 결과를 보기 전에 문서로 고정했다(사전등록). 평가는 2023-01 ~ 2025-12의 36개월이다.
   - 청구금액 가중 WAPE: 기계학습 모델 6.46%, ETS 7.11%, 작년 같은 달 값 9.76%.
     - 작년 같은 달 값보다는 3.30%p 작았고 통계적으로 유의했다.
     - ETS와의 차이(0.65%p)는 유의하지 않았다. 해마다 점추정은 기계학습 모델이 작았지만 36개월로는 우연과 구분되지 않는다.
   - 처음 보는 2026년 1 ~ 6월 자료로 한 **잠정 평가**:
     - 작년 같은 달 값보다 6개월 모두 작았다(6개월 합 2.78%p).
     - ETS보다는 6개월 합으로 0.25%p 컸다(6개월 중 3개월만 작음).
   - 작년 값에 최근 증감률을 곱하는 방식은 수요 수준이 급변한 성분(예: 독감 치료제)에서 크게 빗나갔다(별도 사후 분석).
   - 호흡기 계열 성분(62개)은 모든 방법의 오차가 16 ~ 30%로 크다. 이 성분군에서는 ETS가 기계학습 모델보다 작았다.
3. **급여목록 가격 정보는 성분 단가 예측 오차를 점추정으로 약 15% 줄였지만 유의하지 않았고, 처방량 예측을 개선하는지는 잴 힘이 없었다.**
   - 단가 예측 오차(금액 가중 절대 로그오차)는 목록 가격 경로를 쓴 예측이 0.0186, 사용통계 단가 추세만 쓴 예측이 0.0217이었다.
   - 성분과 가격 변화의 짝을 무작위로 바꾸면 예측이 나빠졌다(p = 0.001). 다만 가격 변화의 시점을 맞춘 효과는 확인되지 않았다.
   - 목록 가격 변화가 청구 단가에 옮겨지는 비율은 중앙값 0.55였다. 목록 변화를 그대로 옮기면 과하다.
   - 처방량 보정은 일부러 넣은 20% 효과도 찾지 못했다. 그래서 '효과가 없다'고 말하지 않는다.

**의미**:
- 급여목록의 처분 예고는 처분 기준으로 대부분 실현됐다. 약국 알림에 쓸 수 있고, 급여정지·중지 예정에는 법원에서 막힐 수 있다는 표시를 함께 두는 것이 맞다(시험하지 않은 제안).
- 비고만으로는 가격 변경의 약 3분의 1만 미리 알 수 있어, 약국 알림에는 매달 목록 비교가 함께 필요하다.
- 전국 성분 처방 시장의 6개월 앞 모니터링에는 ETS를 기본으로 쓴다. 기계학습 모델은 작년 같은 달 값보다 낫지만 ETS보다 낫다는 근거가 없어 운영 모델로 두지 않는다(확정 자료로 다시 평가). 바로 쌓이는 약국 주문·판매 자료가 예측을 더 낫게 할지는 검증하지 않은 가정이다.
- 급여목록 예고 정보는 성분 전체 수요 예측보다 가격·재고 위험 알림에 맞는 정보다(시험하지 않은 제안).

**판정 정밀도**: 규칙을 고치기 전 판정 엔진(v5.2)을 사람 정답 30건(판정 유형별 3건씩, 작성자 1인)과 맞춰 보면 유형 일치는 83.3%였다. 불일치 건만 다시 보고 2건을 고치면 90.0%다(고친 2건은 같은 허가를 이은 경우로, 급여 사건으로는 신규 등재로 볼 여지도 있다). 이 불일치를 보고 규칙을 고친 v5.3의 정밀도는 별도 검증 표본으로 잰다. 유형별 같은 수로 뽑아 모집단 정밀도가 아니며 놓친 사건(재현율)은 재지 않았다. 날짜 일치는 대부분 '그 달 1일' 관례가 양쪽에 같이 적용된 결과라 날짜 판정의 검증으로 보지 않는다.

**용어** — **급여목록**: 건강보험이 적용되는 약과 상한가격의 공식 목록(매달 새 파일). **비고**: 목록의 메모 칸. 앞으로의 처분(예: "'25.7.1. 인하")이 미리 적힌다. **변화 기록표**: 월별 목록 파일을 비교해 언제 무엇이 바뀌었는지 날짜별로 정리한 표. **WAPE**: 예측이 빗나간 양의 합 ÷ 실제 처방량의 합(작을수록 좋다). **원외 처방**: 병원 밖 약국에서 조제되는 처방. **급여정지·중지 예정**: 건강보험 적용을 멈추는 처분의 예정(목록 비고에는 '급여정지'로 적힌다. 제재에 따른 급여정지와 허가 관련 급여중지가 섞여 있고 비고로는 나눌 수 없다). **집행정지**: 처분의 취소소송 등을 낸 쪽이 신청하면 법원이 결정으로 정한 기간(흔히 본안 판결 선고 뒤 일정 기간까지) 처분의 효력이나 집행을 멈추는 것. 결정 전에 먼저 멈추는 잠정 집행정지도 있다. **비고 미기재 약가 변경**: 비고의 예고와 연결되지 않은 약가 변경. 급여목록의 변경으로 확인되며 목록 고시 자체가 예고이므로, 변경이 미리 알려지지 않았다는 뜻은 아니다. **양도양수**: 제품의 허가를 다른 회사가 넘겨받아 같은 약이 새 코드로 다시 실리는 것.

```
docs/          설계(PLAN_P1·P2), 자료(DATA), 결정(DECISIONS), 한계(LIMITATIONS), 요약(SUMMARY), 재현 로그
reference/     표본 점검 스크립트와 기대 출력 (make check-sample의 기준)
reports/       단계별 결과 보고서(내부), 2쪽 요약 SUMMARY.md(P1)·P2_SUMMARY.md(P2), 검토·작업 기록
src/pbd/       코드 (ledger/ = P1, forecast/ = P2)
tests/         시험
outputs/       생성물 (리포트 Markdown은 저장소에 있음, CSV는 생성)
```

## 필요한 데이터
원본은 저장소에 없다. [docs/DATA.md](docs/DATA.md) §1의 표대로 다음을 배치한다.
- `data/raw/`: `benefit/`, `substitute/`, `usage/`(사용통계 원본 96개 CSV), `master/`, `orangebook/`
- `data/sample/`: 표본 parquet 8개 ([data/sample/README.md](data/sample/README.md))

## 설치와 실행
Python 3.11, 디스크 약 5GB (원본 2.3GB, DB 약 1.7GB).
```
make venv                      # .venv 생성, requirements.txt 설치 (약 1~2분)
make check-sample              # 표본 회귀: reference/precheck_v3_output.md와 같아야 한다
make all                       # 적재 → 표본 회귀 → 변화 기록표 → 분석 → 리포트 → P2 → 문서 → 전체 시험
make p2-min                    # P2: 예측용 자료 → 기준 예측 → 모델·진단 → 문서
make report MONTH=2024-09      # 한 달 리포트 → outputs/reports/P1_report_2024-09.md, outputs/dashboard/2024-09/
make test                      # 전체 자동 시험
```
깨끗한 클론 재현(2026-11-19, v1.0 = 6bb4d23): 1차(e933957)는 v4 보관 스크립트 버그로 시험 8개가 실패해 고쳤고, 2차(v1.0)는 새 가상환경에서 처음부터 전체 통과했다(`make all` 1시간 47분, 시험 364개, 결과 CSV 31개·문서 6개가 커밋된 결과와 같음. [reports/REPRODUCTION.md](reports/REPRODUCTION.md)). 이전 판정 규칙 시점의 기록은 [docs/REPRODUCE_LOG.md](docs/REPRODUCE_LOG.md), 그 결과는 `outputs/v4_legacy/`에 읽기 전용으로 있다. `make all`은 P2(`make p2-min`)까지 돈다. 사용자가 정답을 단 검증 표본(`outputs/validation/`)은 저장소에 있고 실행이 덮어쓰지 않는다.

## 예시 리포트
- [2024-09](outputs/reports/P1_report_2024-09.md): 시타글립틴 인하 예고, 아픽사반 등재 예고
- [2025-11](outputs/reports/P1_report_2025-11.md): 토파시티닙 등재 예고, 11월 정기 정비 삭제 611건

리포트는 발간 달까지의 목록과 5개월 전까지의 사용통계만 쓴다. 같은 입력이면 같은 파일이 나오는지는 2026-11-19 깨끗한 재현에서 확인했다.
