# 공개 의약품 데이터로 본 급여목록 처분 예고와 처방 수요

건강보험심사평가원 급여목록의 비고에 미리 적힌 처분 예고(약가 인하·신규 등재·급여중지)를 날짜별 변화 기록표로 정리하고, 예고대로 실행된 비율과 영향 규모를 매달 1일 리포트로 낸다(P1). 같은 정보를 더하면 성분별 전국 처방량(원외 처방, 약국 단위 아님)의 다음 달 예측이 나아지는지도 시험했다(P2). 아래 결론과 숫자는 스크립트가 결과 파일에서 생성한다.

## 핵심 결론

1. **약가 인하 예고는 대부분 예고대로 실행되고, 급여중지 예고는 47%가 법원 집행정지로 막혔다(대부분 두 회사).** 약가 인하 예고는 결과가 난 것 중 99.7%가 예고대로 실행됐다(급여목록 비고에 적힌 예고 기준. 대체조제 목록으로만 보인 막힌 처분까지 넣으면 99.6%). 급여중지 예고는 47.3%(96/203건)가 막혔고, 그중 95건이 두 회사의 처분이다(급여목록 표시만으로 세면 36.0%). 약가 변화의 66.7%(약 3분의 2)는 목록에 미리 예고되지 않았다(일괄 인하가 있었던 3개 달을 빼면 26.8%). 자동 판정을 사람이 정답을 단 처음 보는 검증 표본 30건과 맞춰 보면, 변화의 종류(약가 인하·등재·업체 변경 등)가 90.0% 일치했다(판정 결과를 본 뒤 2건을 고친 정답 기준. 처음 정답 기준 83.3%), 날짜는 100% 일치했다.
2. **예측 정확도는 자료의 신선도가 크게 좌우한다.** 처방량 상위 200개 성분(공개 원외처방 청구금액의 76%)의 다음 달 처방량은, 실제 공개 시차(5개월)에서도 기계학습 모델의 오차가 작년 같은 달 값보다 작았다(WAPE 11.0% vs 12.0%, 금액 가중 6.7% vs 8.5%) (성분별 비교 기준. 달마다 전체 오차를 비교하면 금액 가중 시에만 유의했다). 지난달 자료를 바로 쓸 수 있다면 오차는 7.2%로 더 줄었다. 계절 변동이 큰 호흡기 계열 32개 성분에서는 5개월 시차에서 작년 같은 달 값이 더 나았다. (분류·규모·업체 수로 고르게 뽑은 층화 200개 성분: 유의 — WAPE 10.4% vs 12.1%) 자료가 제때 있다면 상위 200개는 5개월 앞까지, 호흡기 32개는 3개월 앞까지 작년 같은 달 값보다 나았다. 오차는 2개월 앞부터 1개월 앞 대비 약 25%(상위 200개)·33%(32개) 커졌다. (참고: 공개 시차 5개월의 다음 달 예측과 자료가 제때 있을 때의 6개월 앞 예측은 같은 대상 달에서 같은 예측이다. 평가한 달만 다르다(35개월 대 24개월). 작년 같은 달 값이 크게 빗나간 2023년 상반기·2025년 하반기는 다음 달 비교에만 들어 있어, 공통인 24개월만 보면 6개월 앞에서 처방량 합계 기준으로 작년 같은 달 값이 조금 나았다(10.2% 대 10.6%; 성분별로는 200개 중 114개에서 기계학습 모델이 나았다))
3. **급여목록의 가격·등재 정보는 세 대상(32개, 상위 200개, 층화 200개) 모두에서 성분 전체 처방량 예측을 개선하지 못했다.** 실제로 일어난 변화를 미리 알려 준 시험에서도 개선이 없었다. 이것은 목록 정보가 쓸모없다는 뜻이 아니다. 그 정보가 움직이는 곳은 성분 안의 제품별 처방 비중과 약국 재고의 가격 위험일 가능성이 크다고 본다(검증하지 않은 추정). 이 프로젝트는 그쪽을 측정하지 않았다.

**의미**:
- 넓은 성분 범위의 월 수요는 공개 통계로도 예측할 수 있다(상위 200개, 금액 가중 오차 약 7%).
- 자료가 신선할수록 오차가 줄어든다(11.0% → 7.2%).
- 계절 변동이 큰 약(호흡기 계열)은 예외다. 늦은 자료로는 유행 시작을 볼 수 없다.
- 약국 주문·판매처럼 바로 쌓이는 자료의 가치는 이 프로젝트에서 **검증하지 않은 가정**이다.
- 목록 정보는 수요 예측보다 약국 알림에 맞다(시험하지 않은 제안): 약가 인하 예고는 신뢰도가 높고, 급여중지 예고는 법원에서 막힐 수 있다는 점을 함께 표시해야 한다.

**용어** — **급여목록**: 건강보험이 적용되는 약과 상한가격의 공식 목록(매달 새 파일). **비고**: 목록의 메모 칸. 앞으로의 처분(예: "'25.7.1. 인하")이 미리 적힌다. **변화 기록표**: 월별 목록 파일을 비교해 언제 무엇이 바뀌었는지 날짜별로 정리한 표. **WAPE**: 예측이 빗나간 양의 합 ÷ 실제 처방량의 합(작을수록 좋다). **원외 처방**: 병원 밖 약국에서 조제되는 처방. **급여중지**: 건강보험 적용을 일정 기간 멈추는 처분. **집행정지**: 처분에 소송이 걸렸을 때 법원이 판결 전까지 처분의 효력을 멈추는 결정. **양도양수**: 제품의 허가를 다른 회사가 넘겨받아 같은 약이 새 코드로 다시 실리는 것.

## 폴더
```
config/        파라미터(params.yaml), 리포트 설정(report.yaml), 컬럼 대응표, 외부 근거
data/raw/      원본 데이터 (저장소에 없음, 읽기 전용) → docs/DATA.md §1
data/sample/   회귀 시험용 표본 (README만 저장소에 있음, parquet은 따로 받는다)
data/interim/  적재·변화 기록표 DB (pbd.duckdb, 생성물)
docs/          설계(PLAN_P1·P2), 자료(DATA), 결정(DECISIONS), 한계(LIMITATIONS), 요약(SUMMARY), 재현 로그
reference/     표본 점검 스크립트와 기대 출력 (make check-sample의 기준)
reports/       단계별 결과 보고서(내부), 2쪽 요약 SUMMARY.md(P1)·P2_SUMMARY.md(P2), 검토·작업 기록
src/pbd/       코드 (ledger/ = P1, forecast/ = P2)
tests/         시험
outputs/       생성물 (리포트 Markdown은 저장소에 있음, CSV는 생성)
```

## 필요한 데이터
원본은 저장소에 없다. [docs/DATA.md](docs/DATA.md) §1의 표대로 다음을 배치한다.
- `data/raw/`: `benefit/`, `substitute/`, `usage/`(사용통계 원본 96개 CSV), `master/`, `orangebook/`
- `data/sample/`: 표본 parquet 8개 ([data/sample/README.md](data/sample/README.md))

## 설치와 실행
Python 3.11, 디스크 약 5GB (원본 2.3GB, DB 약 1.7GB).
```
make venv                      # .venv 생성, requirements.txt 설치 (약 1~2분)
make check-sample              # 표본 회귀: reference/precheck_v3_output.md와 같아야 한다
make all                       # = p1-all: 적재 → 표본 회귀 → 변화 기록표 → 분석 → 리포트 → 전체 시험
make p2-min                    # P2: 예측용 자료 → 기준 예측 → 모델·진단 → 문서
make report MONTH=2024-09      # 한 달 리포트 → outputs/reports/P1_report_2024-09.md, outputs/dashboard/2024-09/
make test                      # 전체 자동 시험
```
깨끗한 클론 재현 기록은 이전 판정 규칙 시점(2026-11-16)의 것이고, 현재 규칙으로는 다시 하지 않았다 ([docs/REPRODUCE_LOG.md](docs/REPRODUCE_LOG.md)). 이전 규칙의 결과는 `outputs/v4_legacy/`에 읽기 전용으로 있다. P2는 `make p2-min`으로 따로 돌린다(`all`에 넣지 않았다). 사용자가 정답을 단 검증 표본(`outputs/validation/`)은 저장소에 있고 실행이 덮어쓰지 않는다.

## 예시 리포트
- [2024-09](outputs/reports/P1_report_2024-09.md): 시타글립틴 인하 예고, 아픽사반 등재 예고
- [2025-11](outputs/reports/P1_report_2025-11.md): 토파시티닙 등재 예고, 11월 정기 정비 삭제 611건

리포트는 발간 달까지의 목록과 5개월 전까지의 사용통계만 쓴다. 같은 입력이면 같은 파일이 나오는지는 이전 판정 규칙 시점의 재현 기록에서 확인했다.
